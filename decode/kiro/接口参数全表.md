# 接口参数全表（请求 + 返回）

> 只列字段，不给示例。字段名全部来自二进制字面量；`必填` 与 `类型` 标注了可信度。
> **可信度标记**：✅ 实测抓包 · ○ 二进制字符串确证 · △ 由字段簇推断

## 0. 完整度声明（先看这个）

| 项目 | 状态 |
|---|---|
| 字段名 | **完整**（Smithy 生成代码的序列化字面量）+ 少数合并串需按结构拆分 △ |
| 嵌套归属 | 大部分确证；`history` / `additionalContext` / `cachePoint` 的父级归属 △ |
| 必填性 | 只有 `conversationState` 有明确 required 断言；其余按 Smithy 默认 optional △ |
| 类型 | 由字段名与用途推断 △；`bool`/`int` 边界有几处不确定 |
| 枚举值 | 见第 6 节，均为二进制字符串确证 |
| 事件流 `:event-type` 的**大小写形式** | **未恢复**（客户端不匹配该字面量，服务端下发；类型名已确证） |

无法静态恢复的部分，补全方法见第 8 节。

## 12. 补全方法（静态拿不到的那些）

```bash
# 1) 打开请求/响应录制（v2 引擎）
export KIRO_RECORD_API_REQUESTS_PATH=/tmp/req.ndjson
export KIRO_RECORD_API_RESPONSES_PATH=/tmp/resp.ndjson

# 2) 端点指向本地 mock，跑真实流程
python3 /workspace/work/kiro-api-re/mock_server.py 8089
kiro-cli settings api.q.service http://127.0.0.1:8089
KIRO_API_KEY=<key> kiro-cli -vv chat "x"

# 3) 事件流帧头取值（大小写、完整事件名）
python3 /workspace/work/kiro-api-re/decode_eventstream.py /tmp/body.bin
```

仍无法静态恢复：`:event-type` 字面量大小写、`additionalModelRequestFields` 内部 schema、`history` 元素的确切嵌套、各字段的 null 语义。
